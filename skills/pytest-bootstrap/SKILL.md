# Настройка pytest

1. Прочитай инструкции проекта, конфигурацию pytest и существующие тесты. Отсутствие pytest.ini
   само по себе не означает отсутствие тестов: проверь pyproject.toml и принятый запуск.
2. Если тесты уже есть, дополни только нужную конфигурацию и зависимости; форму тестов и фикстуры
   бери из репозитория через [qa-project-style](../qa-project-style/SKILL.md).
3. Для пустого Python API-проекта используй blueprint `python-api-template` в `qa-project-style`.
   Он содержит переносимый каркас с pytest-функциями и offline demo; бизнес-тесты требуют контракта
   текущего продукта. Запрос на создание каркаса уже разрешает его создание в указанной папке.
4. Если пользователь явно выбрал OOP-фреймворк, прочитай [OOP-вариант](references/oop-foundation.md)
   и адаптируй его к выбранному стеку. Этот вариант не задаёт архитектуру остальным проектам.
5. Выполни принятую команду сборки/запуска. Отдельно сообщи результаты offline demo и проверок продукта.

Для UI, мобильных и других стеков сначала определи подходящую конфигурацию; Python API-blueprint
к ним не применяется. Утверждение архитектуры не заменяет утверждение бизнес-кейсов QA workflow.
