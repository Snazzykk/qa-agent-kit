# Генерация API-тестов

1. Прочитай требования, выбранные кейсы и правила проекта. Для qa-agent-kit проверь утверждение плана
   или кейсов; сам вызов скилла не меняет их статус.
2. Для реализации используй [qa-project-style](../qa-project-style/SKILL.md): существующие тесты
   определяют структуру, форму функций/классов, клиентов, фикстуры, assertions и данные.
   Для нового Python API-проекта личный blueprint пользователя — `python-api-template` из этого скилла.
3. Из входного источника выпиши реальные method/path, поля, типы, auth и ожидаемые ответы.
   OpenAPI: учитывай required/nullable, массивы и oneOf/anyOf. Postman: разреши переменные по доступной
   конфигурации. curl: вынеси секреты в имена переменных окружения. Недостающие ожидания уточни.
4. Сопоставь операцию существующему resource client и данным; добавляй только отсутствующие методы,
   модели или фикстуры. Для негативного тела используй принятый raw/dict-путь, если DTO его отвергает.
5. Напиши небольшой diff по ближайшему образцу и проверь его по style_profile. Выполни доступные
   lint/collect/разрешённый прогон; укажи источники ожиданий и отдельно перечисли новые абстракции.

Если пользователь выбрал самостоятельный OOP-фреймворк и подходящего образца ещё нет, можно взять
[OOP-шаблон](references/oop-template.md). Его дерево и BaseTest относятся к этому варианту.
Пример предметной области из blueprint не является спецификацией нового продукта.
