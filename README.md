# qa-agent-kit

Комплект для работы QA-автоматизатора (Python) с Claude Code: скиллы плюс правила и команды-этапы.
Подключаете комплект к QA-репозиторию, заполняете одну анкету и ведёте работу
командами `/audit`, `/plan`, `/gen`, `/feature`, `/triage`. Между этапами решает человек.

Руководство: **`docs/GUIDE.md`** (подключение, настройка, добавление контекста, свои правила и скиллы, проблемы).

Принципы:

- **Новые тесты пишутся в стиле уже существующих** (базовые классы, фикстуры, нейминг, оформление шагов).
- **Репозиторий разработки только для чтения.**
- **Ничего не выдумывается.** Каждый вывод со ссылкой на источник (`файл:строка`, спецификация, требование).
  Нет данных: агент спрашивает, а не додумывает.
- **Состояние хранится в файлах**, а не в истории чата. Новая сессия подхватывает контекст из файлов.
- Без сервера, токенов и установки CLI. Нужны только Python 3.10+, git и Claude Code.

## Зачем это, если есть скиллы

Скиллы остаются основой: они умеют строить индекс кода, писать кейсы, делать каркас фреймворка. Комплект
добавляет вокруг них процесс. Сами скиллы не переписывались, это чужой код.

| Проблема при работе только со скиллами | Что делает комплект |
|---|---|
| Скилл приносит **свой стек и стиль**, а в вашем репо написано по-другому | Стиль существующих тестов главнее шаблона скилла. `/audit` записывает его в `qa-profile.json`, `/gen` пишет «как у вас» |
| Каждый раз формулируете промпт заново | Пять команд-этапов с фиксированными промптами |
| Агент **додумывает**, когда не хватает данных | Проверка перед стартом и правило «нет данных: спроси»; нет ни одного источника: стоп |
| Агент может пойти от аудита сразу к генерации | План и кейсы со `status: draft`; `/gen` не работает, пока вы не поставили `approved` |
| После закрытия чата всё забывается | Состояние в файлах. Новая фича: `/feature`, без повторного аудита |
| Скиллы рассчитаны на доступ к коду разработки | Режим «без кода»: спецификация, коллекции, HAR, стенд, ТЗ, с пометкой источника и уверенности |
| Безопасность держится на внимательности | Репо разработки только для чтения, без запуска против прода, без секретов в файлах, без commit и push |

Чем это **не** лучше. Тяжёлую работу делают скиллы и сам Claude, комплект задаёт рамки. Команды это промпты:
модель может их пропустить или выполнить неточно. Проверено мало (см. «Что проверено и что нет»), цифр выигрыша
(скорости, числа правок) нет. Анкету надо заполнять, комплект поддерживать. Если вы работаете один на
одном проекте и хорошо формулируете промпты, выигрыш скромнее: останутся память между сессиями, контрольные
точки и правило стиля.

От `amq` (CLI с лицензионным сервером) комплект отличается тем, что не использует сервер и токены: вместо
подбора скиллов по коду он добавляет процесс вокруг них. Максимум пользы, когда вы часто входите в новые
проекты или берёте новые фичи, в QA-репо уже есть своя кодовая база, а доступа к коду разработки нет или он
ограничен.

## Быстрый старт

```powershell
# 1. Клонируйте комплект (один раз на машину) и подключите к QA-репозиторию
python C:\tools\qa-agent-kit\setup_project.py C:\work\my-qa-tests

# 2. Заполните project.yml в QA-репозитории (блоки 1-4, минимум: имя и один источник в блоке 2)

# 3. Откройте Claude Code в QA-репозитории и запустите аудит
cd C:\work\my-qa-tests
claude
```

```text
/audit
```

Сначала можно сделать пробный запуск скрипта: `python setup_project.py <путь> --dry-run` (ничего не меняет,
только показывает, что будет сделано).

## Что делает setup_project.py

| Действие | Подробности |
|---|---|
| Команды в `.claude/commands/` | 5 штук, существующие и отличающиеся не перезаписываются (нужен `--update`) |
| Скиллы в `.claude/skills/` | из локальной папки, см. раздел «Скиллы» |
| Правила в `CLAUDE.md` | внутри маркеров, ваш текст не трогается; если файл уже в git, предупредит и не изменит без `--update` |
| `project.yml`, `features/_brief-template.md` | создаёт, если нет; существующие не перезаписывает |
| Хук SessionStart (`.claude/hooks/`, `.claude/settings.local.json`) | `git fetch` и подтягивание при старте сессии, см. «Свежий код и рабочая ветка» |
| `.git/info/exclude` | служебные пути не попадут в коммиты (локально, команда об этом не узнает) |

Не делает: не запускает Claude, не клонирует репозиторий разработки (это делает `/audit`), не трогает
`.mcp.json` и `~/.claude/`, не делает commit.

Повторный запуск безопасен. `--update` обновляет команды, скиллы и блок правил до версии комплекта.

## Скиллы

Скиллы лежат в `skills/` (25 штук, из пака «Agent Mode for Python QA»; происхождение и условия в
`skills/NOTICE.md`). `setup_project.py` копирует их в QA-репо. Лицензия пака именная и запрещает передачу
другим людям, поэтому **репозиторий комплекта должен быть приватным и доступным только владельцу лицензии**,
пока автор письменно не разрешил иное. Не добавляйте в него коллег и не открывайте его публично.

Порядок поиска скиллов скриптом: `--skills-from <папка>`, переменная `QA_KIT_SKILLS`, `<комплект>/skills/`,
`~/qa-skills`. Свои скиллы добавляются в ту же папку `skills/` (см. `docs/GUIDE.md`, раздел 7).

## Анкета project.yml

В файле четыре блока, остальное закомментировано в конце («Дополнительно»). Каждое поле подписано:
формат, пример, что будет, если оставить пустым.

| Блок | Что | Обязательно |
|---|---|---|
| 1. `name` | имя проекта | да |
| 2. `dev_repo` / `sources` / `requirements` | откуда агент узнаёт, как устроен продукт: код, Swagger и стенд, ТЗ | хотя бы один пункт |
| 3. `env` | адрес стенда и команда запуска тестов | нет (пусто = тесты пишем, но не запускаем) |
| 4. `rules` | правила команды по тестам | нет (пусто = стиль берётся из существующих тестов) |

Без источника в блоке 2 `/audit` остановится и спросит. **Секреты в файл не пишутся**, только имена
переменных.

## Сценарии

### 1. Новый проект(с тестами)
```text
/audit       разведка QA-репо (стиль, образцы) + аудит продукта; тесты не пишет
/plan        сверка с требованиями (если они указаны) и план по модулям -> docs/automation-plan.md
             (status: draft). Вы читаете, правите и пишете «план утверждаю» -> status: approved
/gen <модуль>  тесты по утверждённому плану, запуск и отчёт
```

### 2. Кода разработки нет
Оставьте `dev_repo` пустым и заполните `sources` (Swagger, коллекции, HAR, стенд) и/или `requirements`.
`/audit` перейдёт в режим «без кода»: выводы помечаются источником и уверенностью, а раздел
«Ограничения» перечисляет, чего без кода не видно. Нет вообще ни одного источника: агент остановится и
спросит, чем руководствоваться.

### 3. Проект уже разведан, дали задачу на новую фичу
`/audit` заново **не нужен**. Новая сессия Claude Code, затем:

1. Скопируйте `features/_brief-template.md` в `features/<имя-фичи>/brief.md`, заполните (ссылки на Confluence и
   Jira, критерии приёмки, устные договорённости).
2. `/feature <имя-фичи>`: поднимет сохранённый контекст из файлов, проверит, не устарел ли профиль
   (по коммиту), прочитает описание фичи, соберёт в один файл `cases.md` разбор фичи, карту покрытия и список кейсов.
3. Проверьте `features/<имя>/cases.md`, ответьте на открытые вопросы, замените `status: draft` на
   `approved`.
4. `/gen features/<имя-фичи>`.

### 4. Разбор результатов
```text
/triage failures [путь]   почему упали, группировка по первопричине (баг / окружение / тест / неясно)
/triage flaky [путь]      нестабильные тесты (нужна история нескольких прогонов)
/triage impact [ветка]    какие тесты запускать под изменения
/triage bug <тест>        черновик баг-репорта (только если причина подтверждена как баг)
```

## Свежий код и рабочая ветка (автоматически)

Две вещи делаются сами, чтобы не забыть:

1. **При старте сессии** (хук `SessionStart`) в QA-репозитории выполняется `git fetch`. Если вы на основной
   ветке (`master`/`main`), дерево чистое и на сервере есть новое, оно подтягивается (`git pull --ff-only`,
   без слияний). В начале сессии вы видите короткий статус, а агент получает его в контекст.
2. **Перед генерацией тестов** (`/gen`), если вы на основной ветке, агент сам создаёт новую рабочую ветку от
   свежей основной (`qa/<модуль-или-фича>` или по принятому в репо формату) и работает в ней. Если вы уже
   на рабочей ветке, ничего не меняется.

| Ситуация | Что происходит |
|---|---|
| Начало сессии, вы на `master`, чисто, на сервере есть новое | новое подтягивается |
| Начало сессии, у вас есть правки в отслеживаемых файлах | правки не трогаются, подтягивания нет, вы видите предупреждение |
| Вы на рабочей ветке, а основная ушла вперёд | предупреждение (слияние или rebase делаете вы сами) |
| Нет сети или доступа к серверу | предупреждение, работа продолжается по последним известным данным |
| `/gen`, вы на `master` | создаётся новая ветка от свежей `master`, тесты пишутся в неё |
| `/gen`, вы уже на рабочей ветке | ничего не меняется |

Агент не делает `push`, `merge`, `rebase`, `stash`, не удаляет ветки и не переключает вас на другие ветки.

Хук обращается к серверу не чаще раза в 10 минут. Отключить его: `QA_KIT_NO_SYNC=1` или подключить комплект
без него (`setup_project.py --no-hook`). Подробности: `docs/GUIDE.md`, раздел 12.

## MCP (Confluence, Jira)

Скрипт `.mcp.json` не трогает: какой MCP-сервер использует ваша компания, зависит от Confluence/Jira
(облако или on-prem). Подключите его по документации сервера в `.mcp.json` QA-репозитория (токены только в
переменных окружения). В `project.yml` (`requirements.confluence/jira`, раздел «Дополнительно») или в `features/<имя>/brief.md` укажите, какие страницы и задачи
читать. Если MCP не подключён, агент скажет об этом и не будет придумывать содержимое страниц.

## Где лежат результаты (в QA-репо, в git не попадают)

| Файл | Что |
|---|---|
| `artifacts/qa-profile.json` | как устроен QA-репо: стек, структура, образцы, нейминг, как запускать, «запахи» |
| `artifacts/source-inventory.json` | карта продукта (роуты, модели, права, события), с источниками |
| `artifacts/test-matrix.json`, `artifacts/coverage-map.json` | матрица кейсов, карта покрытия |
| `docs/test-plan.md`, `docs/automation-plan.md` | план по рискам; план автоматизации (со сверкой с требованиями) |
| `features/<имя>/` | `brief.md` (ваш ввод) и `cases.md` (разбор, покрытие, кейсы) |

Если результаты нужны команде, коммитьте нужные файлы осознанно (по умолчанию они в `.git/info/exclude`).

## Правила, которые агент соблюдает (из CLAUDE.md)

Репозиторий разработки только для чтения. Тест не подгоняется под текущее поведение: при падении сначала
определяется причина (баг продукта, неясное требование, ошибка теста), решение за вами. Тесты не
запускаются против боевых окружений. Секреты не копируются. `commit`, `push`, смена веток и удаление файлов
только по вашей команде. Нет данных: вопрос, а не догадка.

## Что проверено и что нет

Проверено на практике:
- `/audit` на репозитории `search_by_tables_test`: остановка на пустой анкете с вопросами; разведка QA-репо с
  `qa-profile.json` (пять утверждений агента сверены с файлами, все подтвердились; две неточности он
  отметил сам, самопроверка добавлена после этого прогона и сама не прогонялась).
- Хук (`hooks/qa_sync.py`): сценарии на локальных «серверах» (подтягивание на основной ветке, правки не
  затираются, отставание ветки, нет сети, не git-репо, троттлинг, отключение переменной); слияние с
  существующим `settings.local.json`; в настоящей сессии Claude Code агент увидел сообщение хука.
- `setup_project.py` на временных репозиториях: пробный запуск, установка, повтор, существующий
  `CLAUDE.md` в git, `--update`, нет скиллов, нет git, неверный путь.

Не проверено:
- Автоматическое создание ветки в `/gen`; упрощённый хук (после сокращения тесты хука не повторялись); хук запускался на Windows, на macOS/Linux и
  на корпоративной VDI с ограниченной сетью не проверялся.
- `/audit` с реальным кодом разработки и со спецификацией (режим «без кода» с источником), индекс кода
  (code-graph-analyzer), `/plan` (в том числе сверка с требованиями), `/gen`, `/feature`, `/triage` не запускались ни разу.
- Подключение Confluence/Jira через MCP.
- Работа на корпоративной VDI с ограниченной сетью (скрипту нужен только Python, `/audit` по `url` нужен git-доступ).

Ограничения подхода: без кода разработки выводы опираются на спецификацию и стенд и надёжны настолько,
насколько они актуальны; скрытое поведение и реальные проверки на бэкенде не видны. Оценки приоритетов и
трудоёмкости приблизительные. Результат агента всегда нужно проверять, особенно ссылки на источники и
выводы «не найдено».

```text
qa-agent-kit/
  README.md
  setup_project.py
  commands/    audit, plan, gen, feature, triage
  hooks/       qa_sync.py (fetch и подтягивание при старте сессии)
  templates/   CLAUDE.md.tpl, project.yml, feature-brief.md
  docs/        GUIDE.md (руководство)
  skills/      25 скиллов + NOTICE.md (происхождение и условия лицензии)
```
