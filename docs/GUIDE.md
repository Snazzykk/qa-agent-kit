# Руководство: как подключить, настроить и пользоваться

Коротко «что и зачем» см. в `docs/WHY.md`, порядок работы в `README.md`. Здесь: пошагово, что и куда класть.

## 0. Что нужно на машине

- Python 3.10+ (команда `python --version` должна ответить; на некоторых машинах он называется `py`).
- git (для клонирования комплекта и репозитория разработки).
- Claude Code (команда `claude`).
- Node.js (`npx`) только если подключаете MCP-серверы, которым он нужен.
- Доступ в сеть нужен для `git clone` и самого Claude Code. Остальному (скрипт подключения) сеть не нужна.

## 1. Получить комплект на новую машину

```powershell
git clone git@github.com:<аккаунт>/qa-agent-kit.git C:\tools\qa-agent-kit
```

Скиллы лежат в комплекте (`skills/`), отдельно ничего скачивать не нужно. Репозиторий приватный и
должен оставаться доступным только владельцу лицензии на скиллы (см. `skills/NOTICE.md`).

## 2. Подключить к QA-репозиторию

```powershell
python C:\tools\qa-agent-kit\setup_project.py C:\work\my-qa-tests --dry-run   # посмотреть, что будет
python C:\tools\qa-agent-kit\setup_project.py C:\work\my-qa-tests             # установить
```

Что появится в QA-репо: `.claude/commands/` (6 команд), `.claude/skills/` (скиллы), блок правил в
`CLAUDE.md`, `project.yml`, `features/_brief-template.md`. Всё служебное добавляется в
`.git/info/exclude`, то есть **в ваши коммиты не попадёт**, и команда про это не узнает.

Если в репо уже есть `CLAUDE.md`, ваш текст не трогается: правила дописываются в конец в маркерах
`<!-- qa-agent-kit:begin -->` ... `<!-- qa-agent-kit:end -->`. Если файл уже лежит в git, скрипт предупредит и
не изменит его без `--update`.

## 3. Заполнить project.yml

Все поля подписаны в самом файле (что ожидается, формат, обязательно ли, когда нужно). Три типовые ситуации.

**А. Есть доступ к коду разработки.**
```yaml
name: payments-qa
dev_repo:
  url: git@github.com:company/payments-backend.git
  branch: develop
```

**Б. Кода разработки нет** (самый частый ваш случай). Заполните источники «что есть в продукте»:
```yaml
name: payments-qa
sources:
  api_spec: https://stage.example.com/openapi.json    # Swagger/OpenAPI, ссылка или файл
  collections:
    - .qa-kit/context/payments.postman.json
requirements:
  files:
    - .qa-kit/context/requirements/
```
Нужен хотя бы один источник. Без этого `/audit` остановится и спросит, чем руководствоваться.

**В. Стек не знаете или тесты уже написаны.** Оставьте `stack` пустым: `/audit` определит стек и стиль по
существующим тестам и запишет в `artifacts/qa-profile.json`. Заполняйте `stack` только чтобы переопределить.

Секреты в `project.yml` не пишутся, только имена переменных окружения.

## 4. Добавить контекст

| Что у вас есть | Куда класть |
|---|---|
| ТЗ, требования, выгрузки в файлах (md, txt, pdf, docx, csv, json) | папка `.qa-kit/context/` в QA-репо (например `.qa-kit/context/requirements/`) и путь в `requirements.files` |
| Swagger/OpenAPI | `sources.api_spec` |
| Postman/Insomnia, HAR | `sources.collections`, `sources.har` |
| Страницы Confluence, задачи Jira | MCP в `.mcp.json` (см. ниже) и ссылки в `requirements.confluence/jira` или в `features/<имя>/brief.md` |
| Устные договорённости | `requirements.notes` или раздел «Устные договорённости» в `brief.md` |
| Правила команды по тестам (нейминг, структура, запреты) | файл, например `docs/team-test-rules.md`, и путь в `conventions.file`; короткие правила можно прямо в `conventions.inline` |
| Адрес стенда, команда запуска | `env.base_url`, `env.run_command`; токены только в переменных окружения |

**Все файлы с контекстом (ТЗ, спецификации, коллекции, HAR) кладите в `.qa-kit/context/`.** Скрипт подключения
создаёт эту папку, и она исключена из git (`.git/info/exclude`): документы проекта не попадут в коммит.
В обычных папках репозитория (например `docs/`) git их увидит как неотслеживаемые, и их легко закоммитить
случайно командой `git add .`. Правила команды (`conventions`) можно держать там, где удобно, обычно
это отдельный файл, который команда и так ведёт.

### MCP для Confluence и Jira

Скрипт `.mcp.json` не создаёт: какой MCP-сервер у вашей компании, зависит от Confluence/Jira (облако или
on-prem). Добавьте сервер в `.mcp.json` в корне QA-репо по документации сервера. Структура файла такая:

```json
{
  "mcpServers": {
    "confluence": {
      "command": "<команда запуска из документации сервера>",
      "args": ["<аргументы из документации сервера>"],
      "env": { "CONFLUENCE_TOKEN": "${CONFLUENCE_TOKEN}" }
    }
  }
}
```

Название пакета и имена переменных берите из документации выбранного сервера или у администраторов.
Токен держите в переменной окружения, а не в файле. Claude Code может спросить разрешение на запуск
проектного MCP-сервера при первом использовании. Если MCP не подключён, агент скажет об этом и не будет
придумывать содержимое страниц.

## 5. Первый запуск (чек-лист)

1. `python setup_project.py <qa_repo>`: прошло без ошибок.
2. Заполнен `project.yml` (минимум один источник).
3. `cd <qa_repo>` и `claude`.
4. `/audit`. Прочитайте таблицу проверки перед стартом. Если агент задал вопросы, ответьте.
5. Откройте `artifacts/qa-profile.json`: правильно ли он понял ваш стиль и образцы тестов? Исправьте
   `existing_tests.reference_tests` в `project.yml`, если выбрал не те.
6. Прочитайте итог в чате и `docs/test-plan.md`. Сверьте несколько ссылок `файл:строка` вручную.

## 6. Работа по сценариям

Подробно в `README.md`, раздел «Сценарии». Кратко:

- **Новый проект:** `/audit` → `/reconcile` (если есть требования) → `/plan` → вы пишете «план утверждаю» →
  `/gen <модуль>`.
- **Новая фича на уже разведанном проекте:** новая сессия; `features/<имя>/brief.md` из шаблона;
  `/feature <имя>`; проверка `cases.md` и `status: approved`; `/gen features/<имя>`.
- **Разбор результатов:** `/triage failures | flaky | impact | bug`.

Утверждение плана или кейсов это ваше действие: поменять первую строку файла со `status: draft` на
`status: approved` (или попросить агента это сделать, когда вы сказали «утверждаю»). Без этого `/gen` не стартует.

## 7. Как добавить свои правила, скиллы и команды

**Правила для агента** (общие для всех проектов): `templates/CLAUDE.md.tpl`. После правки запустите
`setup_project.py <qa_repo> --update` в каждом проекте, где нужно обновить блок.

**Свой скилл:** создайте папку `skills/<имя>/` с файлом `SKILL.md`:

```markdown
---
name: <имя>
description: Одно предложение: что делает и когда звать (по описанию Claude решает, когда его использовать).
---

# Заголовок

Инструкции для агента: шаги, правила, формат результата.
```

Шаблоны кода кладите в `skills/<имя>/templates/`. Затем `setup_project.py <qa_repo> --update`.

**Свою команду-этап:** файл `commands/<имя>.md` (в начале блок `description` и при необходимости
`argument-hint`; `$ARGUMENTS` подставляет то, что вы написали после команды). Затем `--update` в проектах.

**Правила команды для конкретного проекта:** `conventions` в `project.yml` (не в комплекте, а в QA-репо).

## 8. Обновление комплекта

```powershell
git -C C:\tools\qa-agent-kit pull
python C:\tools\qa-agent-kit\setup_project.py C:\work\my-qa-tests --update
```

`--update` перезаписывает команды, скиллы и блок правил версией комплекта. Если вы вручную правили
скопированный скилл или команду в проекте, эти правки будут потеряны: вносите их в комплект, а не в
копию. Свой текст в `CLAUDE.md` вне маркеров не затрагивается.

## 9. Git-гигиена в QA-репо

- Служебное (`.claude/`, `CLAUDE.md`, `project.yml`, `artifacts/`, `features/`, `.qa-kit/`, планы в `docs/`)
  по умолчанию в `.git/info/exclude`, в коммиты не попадает.
- Если эти пути уже отслеживаются git (например, раньше туда закоммитили чужой пак), exclude на них не
  действует: уберите их из индекса вручную (`git rm -r --cached <путь>`). Скрипт этого не делает.
- Если команде нужны результаты (например, `docs/test-plan.md` или кейсы фичи), коммитьте их осознанно,
  вызвав `git add -f <путь>`.
- Новые тесты, которые написал агент, остаются неотслеживаемыми: просмотрите diff и закоммитьте сами.

## 10. Типовые проблемы

| Симптом | Что делать |
|---|---|
| Команды `/audit` и другие не видны | Перезапустите сессию Claude Code в корне QA-репо; проверьте, что есть `.claude/commands/` |
| «скиллы не найдены» при установке | Скиллы лежат в `<комплект>/skills/`; проверьте, что клонировали комплект целиком; либо `--skills-from <папка>` |
| `python` не найден | Попробуйте `py`; установите Python 3.10+ |
| `/audit` сразу остановился с вопросами | Так и должно быть: нет источников в `project.yml`. Заполните или ответьте на вопросы |
| Не клонируется репо разработки | Проверьте доступ (SSH-ключ или токен в настройках git). Пароли в `project.yml` не пишите |
| Индекс кода не поднимается | Агент предложит запасной вариант или вариант без графа; решение за вами |
| Профиль устарел после изменений в тестах | `/feature` сам обновит затронутые разделы; полный пересбор: `/audit` |
| `/gen` отказывается стартовать | Нет утверждения: `status` в плане или `cases.md` ещё `draft` |
| Агент выдал вывод без ссылки на источник | Это нарушение правил: попросите источник или перепроверку; не принимайте такой вывод |
| Тест упал, агент хочет «поправить ожидание» | Остановите: сначала причина (баг продукта, неясное требование или ошибка теста), решение ваше |

## 11. Что делать, если агент ведёт себя не по правилам

Команды это промпты, модель может отступить от них. Признаки: пропущена проверка перед стартом,
сгенерированы тесты без утверждённого плана, нет ссылок на источники, тест подогнан под ответ приложения.
Остановите и напомните правило из `CLAUDE.md`. Если нарушение повторяется, поправьте формулировку
в `commands/<имя>.md` или `templates/CLAUDE.md.tpl` и сделайте `--update`.
